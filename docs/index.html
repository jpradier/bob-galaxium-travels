Test details

What was measured

The test consisted of planning and implementing a complex new feature in the Galaxium Travels application — a live Node.js travel-booking app. The feature adds seat class selection (Economy, Business, and Galaxium class) to the flight booking flow. Both tools received the exact same two-prompt sequence, starting in Plan mode and proceeding to Agent mode.

Qualitative observations

Beyond raw cost: what's different about how each tool works

IBM Bob
Bob Correct in one shot — no rework

Bob produced a correct, complete implementation on the first attempt. GitHub Copilot's first draft contained errors that required one additional iteration to fix — adding time, tokens, and cognitive overhead for the developer.

Bob Cost visible at every step

Bob surfaces consumption inline in the chat window after each task. Developers see the dollar impact of every iteration in real time, enabling immediate course corrections — tighten the prompt, disable an idle MCP server, or stop before an expensive re-run.

Bob Diffs directly in the chat window

File differences appear inline in the chat window before any change is applied, keeping the developer in flow. Diffs are also accessible at any time from the Source Control menu — the same way GitHub Copilot exposes them — so neither approach is blocked.

Bob Consumption analytics one click away

Bob's cost analytics are reachable with a single click directly from the chat view. GitHub Copilot requires navigating to a separate billing dashboard outside the IDE, adding friction for teams that want to monitor spend while they work.

Bob Simpler permissions model

Bob's allow/deny permission flow is straightforward and IDE-agnostic. Approving or blocking a file write is a single explicit action, with no layer of extension or workspace-level configuration to navigate.

GitHub Copilot
Copilot Larger context window

GitHub Copilot ships with a 1 M-token context window vs Bob's 270 k. On very large codebases this delays compaction, but in this test it did not translate to a speed or quality advantage — Copilot ran parallel subtasks yet still took 25% longer.

Copilot Opaque cost model

The $3.60 figure represents Premium Request credits consumed against the Pro Plan flat fee. Actual marginal cost is invisible during work. Once the monthly allowance is exhausted, overage rates apply — making real per-task cost hard to track without a separate billing dashboard.

Bob's frugality practices

Cost transparency drives spending-aware habits — not available in Copilot

1
Write more specific prompts

Seeing cost per turn in real time teaches developers that vague prompts lead to clarification rounds — and that each round costs money. Specificity up front reduces iterations and total spend.

2
Disable unused MCP servers

Every connected MCP server adds tokens to the system context on every request. Bob makes active servers visible and easy to toggle — removing idle ones cuts baseline cost per turn immediately.

3
Automatic context compaction

Bob compresses conversation history when the 270 k window fills, keeping per-turn costs predictable. Copilot's 1 M window silently accumulates context, increasing cost per API call without feedback to the developer.

Caveats

What this number is, and isn't

Read before quoting

  • This is a single run, not a statistically significant benchmark.
  • Cost reflects raw token / credit consumption end-to-end on this one prompt; output quality and completeness still need a side-by-side review.
  • Real-world cost depends heavily on prompt style, iteration count, and how often the user redirects the agent.
  • Copilot's $1.08 represents 27 Premium Requests (Claude Sonnet 4.6 at ×9 multiplier) consumed against the Pro Plan $10/month allowance. Once the allowance is exhausted, overage rates apply — direct comparison with Bob's metered cost requires care.
  • Bob's dollar value shown on this page = BobCoins ÷ 2. Bob consumed 3.39 BobCoins = $1.70 USD.
